# RINEX 3.04 观测数据格式修正

## 问题描述

RINEX 3.04标准中，对于每个历元的每个卫星的观测数据，**必须按照RINEX头中`SYS / # / OBS TYPES`定义的观测类型顺序来输出**，而不是按照实际接收到的信号顺序。

## 关键改动

### 1. 观测数据顺序

**修改前**：按照信号接收的顺序输出观测数据
```
不正确 × 观测顺序由数据接收顺序决定
```

**修改后**：严格按照RINEX头定义的顺序输出
```
正确 ✓ 观测顺序由头中的 SYS / # / OBS TYPES 定义
```

### 2. 缺失观测处理

缺失的观测值**必须用16个空格补齐**，以维持列对齐。

### 3. 多行观测格式

当一个卫星的观测数据超过4个（最多4个观测/行，每个16字符）时：

- **第1行**：`{SYS}{PRN:>2}` + 最多4个观测
- **后续行**：8个空格（对齐卫星ID位置）+ 最多4个观测

#### 示例（Galileo有20个观测类型）：
```
E25  25924945.931   136236510.94947       640.392          47.250    25924948.844   101735067.04108       478.143          48.250
        25924944.478   110581578.10608       519.749          48.800    25924945.339   104389011.89008       490.654          48.600
        25924947.421   103062040.85008       484.406          50.700                                                    
```

- 第1行：卫星ID(3) + 4个观测(64) = 67字符
- 第2行：空格(8) + 4个观测(64) = 72字符
- 第3行：空格(8) + 1个观测(16) + 缺失观测(48) = 72字符

## RINEX头中的观测类型定义

头中定义示例（BeiDou C系统）：
```
C   20 C1P L1P D1P S1P C2I L2I D2I S2I C5P L5P D5P S5P C6I L6I D6I S6I C7I L7I D7I S7I
```

观测数据行必须**严格按照这个顺序**输出每个观测值。

## 实现细节

### 修改的方法：`RINEX3Writer._write_satellite_observations()`

```python
def _write_satellite_observations(self, sat_data: Dict) -> None:
    # 获取该系统的观测类型列表（来自头）
    expected_obs_codes = self.sys_obs_types.get(sys, [])
    
    # 按照头定义的顺序遍历每个观测类型
    for obs_code in expected_obs_codes:
        # 如果有该观测，输出16字符格式
        # 如果没有，输出16个空格
        
        # 每4个观测后换行（续行前需加8个空格）
        if field_count % 4 == 0 and field_count < len(expected_obs_codes):
            line = "        "  # 8个空格用于对齐
```

## 验证方式

生成的RINEX文件应该：

1. ✓ 每行最多包含4个观测（每个16字符）
2. ✓ 观测顺序严格按照头中定义
3. ✓ 缺失观测用16个空格占位
4. ✓ 续行前有8个空格对齐
5. ✓ 可被标准工具（RTKLIB、Converto等）正确读取
